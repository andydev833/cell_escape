## 今回の拡張

1〜5は既存の設計を継承し、6〜30を追加する。移動だけでなく、選択、セル内容の操作、編集モード、検索・置換、位置指定、フィルター、値と書式の分離、メモ、数式参照、新しいシートへ幅を広げる。

全30種類のショートカットを無理に割り当てることはしない。最終面は総合問題とし、前に覚えた操作を繰り返し使う。

キー名と機能名は設計者向けの情報。ゲーム本編とクリア後は学習の説明を出さず、右上「？」を押したときだけ手掛かりと必要なら解法を表示する。

## 共通の設計原則

- 初見で引っかかりやすい罠を置くが、一回以上の死亡を正解条件にしない。
- 一歩目で理由不明に殺さない。通常移動を試す安全な足場と、観察できる手掛かりを設ける。
- 前の部屋で成功した方法が、次の部屋では足りない・巻き込む・逆効果になる組み合わせを利用する。
- 罠の因果を視覚化する。何が落ち、何が検知され、何が消えたかを、失敗画面より先に見せる。
- 基本UI、音オフ、演出軽減、段階ヒント、即リトライは既存設計v0.4を維持する。
- 正解キーを押した履歴ではなく、値・書式・選択・位置・装置状態を判定する。同じ正しい状態を作れる別手順は基本的に許容する。
- Ctrl＋Zで死亡や歩行を巻き戻さない。Deleteでセルの床や座標を消さない。太字でキャラを重くしない。操作の実際の意味を保つ。
- 指定の座標以外を飾りのために埋め、Ctrl移動・使用範囲・現在領域を意図せず変えない。
- 装置、床、危険条件はセル内容と別に持つ。空白セルにも床を置ける。
- 新しい操作モードや装置が増えても、常設の講義パネルや長い説明を追加しない。

## 各ステージの記述の精度

1〜5は既存の座標を継承する。6〜30は主要な装置・状態・手順を定めた設計であり、見た目の全セル、移動可能セル、装飾、カメラなどの最終盤面データは実装時に整合させる。未定義のセルを推測で危険セルにして、手順を不成立にしない。

実装前に各ステージのvalues、walkable、hazards、start、exit、装置条件を一つのデータ定義へ落とし、正解ルートと誤操作ルートの両方を検証する。6〜30の到達性や操作キーの実機検証が完了したという意味ではない。

## Stage 01「一歩目。」

- **主な操作：** Ctrl＋→。
- **配置：** B5開始、L5出口。B5:L5の値は連続。B5:E5が安全、F5:K5が着地すると発動する落下プレス。
- **引っかけ：** 右へ普通に歩く。最初の3歩は安全で、4歩目のF5でプレスが落ちる。
- **正解：** B5/C5/D5/E5のいずれかからCtrl＋→でL5へ移動。中間の罠には着地しない。
- **正解条件：** L5へ到達。
- **ヒント：** 「あの床に止まらず進めないかな？」→「矢印にもう一つのキーを」→「Ctrl＋→」。
- **注意：** 罠の演出、失敗表示、再挑戦はv0.4の設計を適用。最初の入力では殺さない。

## Stage 02「見えている出口」

### 狙うショートカット

Ctrl＋↓。Ctrl＋矢印の方向を使い分ける。

### 部屋の構成

上段に、ステージ1とよく似た横長の通路と光る扉がある。途中に下への枝道、下段にも別の出口が見える。

| 位置 | 役割 |
| --- | --- |
| B3 | 開始 |
| B3:E3 | 上段の安全区間。右に3歩は安全 |
| F3:K3 | 上段の着地トラップ |
| L3 | 出口のように見える罠 |
| E3:E7 | 下への枝道 |
| E4 | 枝道の最初の安全床 |
| E5:E6 | 枝道の着地トラップ |
| E7:H7 | 下段の安全区間 |
| I7:K7 | 下段の着地トラップ |
| L7 | 本当の出口 |

移動先計算用の値は、B3:L3、E3:E7、E7:L7をすべて非空白にする。重複するE3・E7は同じセル。これ以外は空白。

### 引っかかりそうな動き

B3でCtrl＋→を押す。前の部屋なら出口だったL3へ、一気に到着する。

ところが、扉の前の床板が抜け、キャラが下の歯車へ落ちる。扉の光が消え、偽物だったことが見える。失敗表示より先に、床の開口と落下を見せる。

「出口へ飛べばよい」という直前の成功体験を使う。見せかけの扉は初見でも完全に区別不能にはせず、歪んだ枠や下側の切れ目を小さく入れる。

### クリア手順

1. →を3回押してB3からE3へ歩く。
2. E3でCtrl＋↓を押し、E7へ移動する。
3. E7でCtrl＋→を押し、L7の出口へ移動する。

E3から普通に下へ進むと、E4は安全だがE5で床が崩れる。下段も普通に右へ進む場合、最初の3歩までは安全にする。

### 手掛かりと「？」

- 盤面：E3に下へ続くレール、下段の本当の扉に外から漏れる明かり。
- ヒント1：「明るい扉が、本物とは限らない。」
- ヒント2：「途中の床から、下にも続いている。」
- ヒント3：「右に3歩。Ctrl＋↓、それからCtrl＋→。」

### 判定

L3へ着地すると偽出口の罠で死亡。L7へ着地したときだけクリア。通路外の移動は不成立とし、別ルートの出口にしない。

## Stage 03「ひとりでは開かない」

### 狙うショートカット

Ctrl＋Shift＋→。データの端まで選択範囲を広げる。

### 部屋の構成

横の通路に5枚の感圧板と、対応する5つの消灯したランプ。先には閉まった扉がある。感圧板には同じ図柄を描き、5枚で一組だと分かるようにする。

| 位置 | 役割 |
| --- | --- |
| B5 | 開始 |
| B5:E5 | 安全区間 |
| F5:J5 | 5枚の感圧板 |
| K5 | 扉手前の安全床 |
| L5 | 出口。5枚の装置が同時に反応すると開く |

セルの値はB5:J5を非空白、K5を空白、L5を非空白とする。床はB5:L5に連続して存在する。

### 引っかかりそうな動き

Ctrl＋→でJ5へ飛ぶ。感圧板が1枚だけ反応し、残り4つのランプが消えたままになる。次の瞬間、床から針がせり上がってキャラが弾ける。

普通に歩く場合も、C5・D5・E5までは安全。F5へ単独で踏み込むと同じ罠が発動する。

### クリア手順

1. B5でCtrl＋Shift＋→を押し、B5:J5をまとめて選ぶ。
2. 選択範囲の中にF5:J5の5枚すべてが入り、5つのランプが同時に点灯する。
3. 扉が開き、感圧板の罠が解除される。
4. Ctrl＋→でJ5へ移動する。
5. もう一度Ctrl＋→で、空白のK5を越えてL5へ到着する。

範囲を選んだ時点では、主人公＝アクティブセルはB5に残る。半透明の選択枠が伸び、装置だけが一斉に反応する。主人公がJ5へ移動したようには描かない。

### 装置と選択のルール

- F5:J5がすべて同じ選択範囲に含まれたら解除。
- B5:E5などの安全セルが余分に含まれていてもよい。
- 部分的な選択だけでは死亡させない。Shift＋→で徐々に範囲を広げても正解状態へ到達できる。
- 主人公が単独で感圧板へ着地し、まだ解除されていない場合に罠が発動する。
- 一度5枚同時に反応したら解除は保持する。選択を解除した瞬間に再発動させない。
- 不必要なEnterによる「選択の確定」操作は追加しない。

### 手掛かりと「？」

- 盤面：5つの同じ装置と5つのランプ。1つだけ踏むと1つだけ反応する。
- ヒント1：「ひとつだけでは、開かない。」
- ヒント2：「自分が動かず、床をまとめて囲めないかな？」
- ヒント3：「Ctrl＋Shift＋→でまとめて囲む。開いたら、Ctrl＋→で進もう。」

| C5 | 台座A。初期状態で石が一つある |
| H5 | 台座B。初期状態は空 |
| L5 | 出口。石が両方の台座にあると安定して開く |
| B5:L5 | 歩行可能な床 |

セル値はB5:G5およびI5:L5を非空白とする。そのうちC5を石トークンにし、H5は空白。床の見た目と値は別データとして扱う。

### 引っかかりそうな動き

光が漏れているので、いつものように出口へ進む。台座Bが空のままL5へ着地すると、扉の支持が外れて、上から重い扉が落ちてくる。

失敗時には、消えたままの2つ目のランプと、落ちた扉を同時に見せる。「通路のどこかにランダムな罠」ではなく、装置が片側しか満たされていないことが原因だと後から分かるようにする。

空のH5に立つだけでは石を置いたことにならない。範囲選択で両方の台座を囲んでも、この部屋の台座はセル内容の石に反応する。前室の感圧板とは、石の輪郭と窪みのある形で区別する。

### クリア手順

1. →でC5の石へ移動する。
2. Ctrl＋Cで石のセルをコピーする。コピー元の点線枠を表示する。
3. Ctrl＋→でG5へ移動する。H5は空白なので、ここが連続データの端。
4. →でH5へ進む。H5は安全な台座。
5. Ctrl＋VでH5へ石を複製する。
6. C5の石が残り、H5にも石が現れ、2つのランプが点灯する。
7. Ctrl＋→でL5へ進み、脱出する。

歩いてH5へ行ってもよい。移動の最短手順を暗記しないと解けない仕掛けにはしない。

### 成功と失敗の条件

- 正解は「C5とH5の両方が石トークン」であること。
- 任意の数字や通常の床データで台座を満たしたことにはしない。
- 切り取りでC5を空にしてH5へ移した場合、台座Aのランプが消える。出口に進むと扉の罠になる。
- H5へ貼り付ける途中では殺さない。失敗は、準備不足でL5へ着地したとき。
- 条件を満たしたら扉はしっかり上がり、2つのランプが光る。開いたことを見た目で分かるようにする。

### 手掛かりと「？」

- 盤面：同じ石の形の2つの台座、1つだけ点灯したランプ、傾いた扉。
- ヒント1：「扉を支えるものが、まだ足りない。」
- ヒント2：「ひとつは残したまま、もうひとつ置けないかな？」
- ヒント3：「C5でCtrl＋C。H5へ移動してCtrl＋V。」

## Stage 05「ふたつはいらない」

### 狙うショートカット

Ctrl＋X、Ctrl＋V。元の内容を残さず別のセルへ移す。

### 部屋の構成

前の部屋とよく似た、左に物体、右に空の受け口がある配置。ただし今回は石ではなく、番号が一つ付いた鍵。扉には鍵穴一つと「I」の紋章があり、監視装置も鍵一つの状態を表示している。

| 位置 | 役割 |
| --- | --- |
| B5 | 開始 |
| C5 | 鍵が置かれた棚 |
| H5 | 鍵の受け口。初期状態は空 |
| L5 | 出口 |
| B5:L5 | 歩行可能な床 |

セルの非空白・空白の配置はステージ4と同じ。ただしC5のトークンは「KEY_05」のように種類を区別した鍵とする。

### 引っかかりそうな動き

前室で覚えたCtrl＋C→Ctrl＋Vをそのまま使う。

するとC5とH5に同じ鍵が二つ存在する。監視装置に二つの鍵の輪郭が光り、赤い走査線が2本の鍵を結ぶ。短い反応の直後にレーザーが閉じて、主人公がセルの破片に弾ける。

コピーが終わった直後の二つの鍵を短く見せ、「増やしたこと」が罠の原因だと伝える。貼り付けと同時に理由不明の死亡表示へ飛ばさない。

### クリア手順

1. →でC5の鍵へ移動する。
2. Ctrl＋Xで切り取り待ちにする。この時点では鍵を消さない。
3. Ctrl＋→でG5へ移動する。
4. →でH5へ進む。
5. Ctrl＋Vで、C5からH5へ鍵を移す。
6. C5は空になり、H5だけに鍵がある。監視装置は鍵一つのままで、扉が開く。
7. Ctrl＋→でL5へ進み、脱出する。

### 成功と失敗の条件

- 正解は「C5が空白、H5が鍵、盤面の鍵トークン総数が1」。
- コピーで鍵が二つになったら、貼り付け確定後に罠を起動する。
- 切り取りは貼り付け時に元と先を同時更新する。更新途中の一瞬だけ鍵が2本と誤判定しない。
- 切り取り待ちだけで扉を開けない。受け口への配置完了が必要。
- まだ鍵が受け口にない状態でL5へ入ると、鍵のない門の落下シャッターで失敗する。
- 検知するのは鍵のトークン数。通常のセル値「1」を鍵として数えない。
- Ctrl＋Zは今回の学習対象には追加しない。死亡後の編集取り消しで復活させない。

### 手掛かりと「？」

- 盤面：鍵穴は一つ、「I」の紋章、鍵数一つを示す監視装置。
- ヒント1：「ここに必要なのは、ひとつだけ。」
- ヒント2：「増やすと見つかる。元の場所には、残さない。」
- ヒント3：「C5でCtrl＋X。H5へ移動してCtrl＋V。」


## Stage 06「その返事でいい？」

**設計者向けの意味：** 開いているダイアログを閉じる

### 部屋と手掛かり

B5開始。部屋の中央に、光る扉の絵と大きな「OK」があるゲーム内確認パネル。下には小さく鍵が砕ける図柄。通路はB5:L5で、初期状態の鍵は正しくセット済み。

### 初見で引っかかる想定と罠

入口の装置で開くパネルに、そのままEnter／OKと答えると鍵を処分してしまい、閉鎖シャッターが落ちる。開始ボタンのEnterを同じパネルへ二重適用しない。

### クリア手順

1. E5の装置まで安全に歩く。装置で確認パネルが開く。
2. Escで確認パネルを閉じる。鍵を処分する変更は確定させない。
3. パネルの陰に見えていた通路を抜け、L5へ進む。

### 正解条件

確認操作がキャンセルされ、鍵が残った状態でL5へ到達。

### 「？」の三段階ヒント

1. その返事で、本当に大丈夫？
2. 進むことだけが、選択じゃない。
3. その窓はEscで閉じられる。

Escは確定済みの削除や死亡を戻さない。パネルはゲーム内の架空の確認。既存の開始・ヒント・設定画面とは別。キャンセルボタンで同じ状態にしても正解。開始時から自動で隠し罠にせず、安全に装置へ近づける。

## Stage 07「鍵は、返して」

**主なショートカット：** Ctrl＋Z  
**設計者向けの意味：** 直前のセル編集を元に戻す

### 部屋と手掛かり

C5に固有IDを持つ電池があり、入口側の橋へ給電している。H5に電池を差すと出口の機械錠は一度だけ解錠されるが、入口側の給電が切れ、I5の橋が沈む。

### 初見で引っかかる想定と罠

前室の切り取りを使ってC5からH5へ電池を移し、そのまま出口へ進むと沈んだ橋へ落ちる。電池をコピーして二つにすると重複監視装置に見つかる。

### クリア手順

1. C5の電池をCtrl＋X、H5でCtrl＋V。出口の錠が解ける音と、橋の消灯が同時に起きる。
2. 移動を続ける前にCtrl＋Zで、直前の切り取り貼り付けを取り消す。
3. 電池がC5へ戻り橋が復旧する。解錠済みの機械錠を通って出口へ。

### 正解条件

機械錠の解錠ラッチがON、C5に電池、H5は空、電池総数1の状態で出口へ。

### 「？」の三段階ヒント

1. 開いた。でも、渡れない。
2. 動かしたものを、元の場所へ戻せないかな？
3. 貼り付けた後、Ctrl＋Z。

### 実装時に守ること

最初から架空のUndo履歴を入れない。プレイヤー自身の切り取り貼り付け1回を履歴へ記録する。Undoはセルの値だけを戻し、既に外れた機械錠のラッチは戻らない世界装置として明示する。歩行・死亡・時間全体を巻き戻さない。死んだ後は再挑戦する。

## 実装担当への共通仕様

### 入力モードを分ける

30ステージへ拡張する際は「盤面移動」「範囲選択」「セル内編集」「コマンドパネル」「ヒント・設定」「失敗・クリア」を分ける。

- セル内編集中のRは文字。通常画面のR再挑戦へ流さない。
- Ctrl＋Rは右方向へのコピー。R再挑戦やブラウザー更新へ誤って流さない。
- 編集中のEnterは確定。失敗画面のEnterは再挑戦。開始ボタンのEnterを次のパネルへ二重適用しない。
- F2中の矢印は文字カーソル、通常画面の矢印はセル移動。
- Ctrl＋Enterは複数セルへの確定。普通のEnterと同じ処理へ落とさない。
- コマンドパネル内の入力をセル値へ直接流さない。
- ヒント・設定はゲームを停止する。検索・置換などゲーム内コマンドは、確定した操作を一つのアクションとして適用する。検索結果などに伴う到着先の罠判定を省略しない。
- 検索窓はEnterで検索、Escで閉じる。セルの移動結果が罠なら、コマンド表示よりゲームの失敗表示を優先して原因を見せる。ヒントの一時停止と、結果を確定するコマンドの処理を混同しない。

### 最低限必要になるデータ

- ワークブック：シートの識別子、順序、新規挿入、アクティブシート。
- シート：セル値、数式、表示用書式、使用範囲、連続領域、メモ、フィルター。
- 選択：アクティブセル、起点、端点、全行・全列などの範囲。
- 編集：下書き、文字カーソル、確定・取り消し。
- クリップボード：コピー／切り取り、元の範囲、値・数式・書式。貼り付けトランザクション。
- 履歴：セル編集のUndo。歩行・死亡・世界全体の時間を含めない。
- ゲーム装置：ラッチ、光学検査、鍵の総数、電源など。編集履歴へ含めるものと世界の装置として保持するものを明示する。
- 演出：罠の発動時刻、着地、停止、再開、試行ID。前の試行の遅延処理を残さない。

全Excel機能を作る必要はない。各部屋で必要な範囲の意味を正しく実装する。28の数式も、数値・セル参照・絶対参照・乗算など、対象式を扱う小さなモデルから始める。結果だけを正解値14へ置き換える実装にはしない。

### 値・書式・表示を分離する

24〜28はここを混ぜると謎が成立しない。

- 値731と文字列「731.00」は同じ型ではない。
- 数値書式を変えても元の数値は731。
- 赤い塗りつぶし、太字などは書式。
- 値だけ貼り付けは、貼り付け先の書式を保つ。
- 数式をコピーした場合の相対参照の移動を扱う。
- メモを読んでもセルの値は変わらない。

### 検索・置換・フィルターの具体性

コマンドはゲームの世界観に合わせた小さなパネルとしてよいが、機能の意味を変えない。

- 検索：セルの内容の一致先を探す。番地入力とは別。
- 置換：対象範囲、検索文字、置換文字、部分一致／全体一致を明示する。
- ジャンプ：有効なセル番地を解析する。データの端への移動とは別。
- フィルター：有効化だけと条件選択を区別し、隠れたデータを消さない。
- 保護されたセル：不許可の編集は受け付けず、入力が通ったように見せない。壁と同じく、不成立操作だけで必ず死亡させる必要はない。

## ブラウザーとOSのキー競合

Windows版Excelの機能を基準にした設計であり、全キーが全ブラウザー・Macで取得できると確認したものではない。

- Ctrl＋1、Ctrl＋5などブラウザーのタブ切替に直結するキー、Ctrl＋W、Ctrl＋N、Ctrl＋Tabは本編30の必須解法から外した。
- Ctrl＋R、Ctrl＋F、Ctrl＋H、Ctrl＋G、Ctrl＋B、Ctrl＋Space、F2、Shift＋F2、F4、Shift＋F11は、対象ブラウザー・OSで入力取得と既定動作の抑制を先に検証する。
- JISとUSの記号キー、Shiftを含む数字キーは、文字と物理キーの違いを確認する。25の数値形式は対象Excelの配列で検証する。
- MacはOSの入力ソース切替やMission Controlとの競合がある。単純にすべてのCtrlをCommandへ変える仕様にしない。
- ブラウザー側で取得できないキーを、黙って別のキーとして教えない。提供方式、正しい代替操作、必要ならデスクトップ版を検討し、そのステージの対応状況を明記する。
- OSの設定変更をユーザーの許可なく実行しない。
- 完全なブラウザー互換性が必要なら、実装前に競合キーだけの小さな動作確認を行う。

## 受け入れ条件と試遊

各ステージを実装するときに、次を用意する。

1. 初期値・書式・メモ・装置・移動可能範囲・出口条件の完全なデータ。
2. 本書の正解手順でクリアできる確認。
3. 本書で想定した誤操作が、指定の原因で失敗する確認。
4. 最初の普通の一歩が理不尽な即死にならない確認。
5. 正しい別手順や初見無死亡を拒否しない確認。
6. 音なしでも原因が見える、動きを控えめでも理解できる、即再挑戦できる確認。
7. ヒント・設定・フォーカス離脱・キー長押し・編集入力との衝突確認。
8. 必要なショートカットが実際の対象端末で取得できる確認。

16〜17、19、24、28は値が変わった後のCtrl移動・使用範囲にも注意する。初期の盤面だけで作った固定ルートにしない。

ステージ6〜30について、実装コードの到達性、ブラウザー入力、映像、初見の失敗率は未検証。既存2〜5では、前の設計時に4つの正解ルートと4つの失敗パターンの設計モデルを確認しているが、30面すべてのゲームが動くと確認したわけではない。

## 実装の進め方

全30ステージを同時に作り込む前に、共通のセル・選択・編集・履歴・書式のモデルを揃える。実装順は1〜5の調整後、6〜10、11〜17、18〜24、25〜30を目安とする。

この順は制作上の提案であり、ゲーム中に「基礎編」「学習編」と表示するための分類ではない。部屋名と世界の変化だけで進行を見せる。
